# WebUI 导航工作台

在运行 ROS 2 的 Ubuntu 主机上编译工作区后启动。已有工作区升级时，重新编译 `backend`、`bringup`、`nav_terrain`、`nav_behaviors`、`nav_bringup` 和 `chassis_comm`。

```bash
cd ~/yang_nav
source /opt/ros/jazzy/setup.bash
colcon build --base-paths src --packages-select backend bringup nav_terrain nav_behaviors nav_bringup chassis_comm --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
bash tools/start_web_ui.sh --port 8080
```

在受信任的局域网内，用浏览器访问 `http://主机局域网IP:8080` 即可直接使用工作台。用 `--host 127.0.0.1` 可限制到本机。WebUI 与业务节点使用同一个 `ROS_DOMAIN_ID`，未设置时为 `0`。

WSL 默认 NAT 环境下，Windows 本机可以访问 `http://localhost:8080`。其他设备通过 Windows 局域网 IP 访问时，需要将 TCP `8080` 转发到 WSL 的 IPv4 并放行主机防火墙。使用 Foxglove 时同样处理 TCP `8766`。WSL 开启镜像网络后，按主机防火墙配置放行所用端口即可。Ubuntu 真车直接使用车上的局域网地址。

在本机 WSL 环境已配置端口转发时，WSL IPv4 变化后需更新转发目标。可在管理员 PowerShell 中用 `wsl -d ubuntu24 -- hostname -I` 查看新地址，用 `netsh interface portproxy show v4tov4` 查看现有规则。

## 日常操作

打开「运行工作台」即可在同一页查看运行状态、管理进程、设置模式与地图、录包及复制 Foxglove 地址。页首快捷链接可跳到相应区块；「运行日志」默认折叠，展开后可按进程查看。

操作按钮点击后直接提交，不弹出二次确认。操作真车或发送目标前，请先确认周围安全；关闭全部前请停稳。

1. 在「模式与地图」选择仿真或真车、单或双雷达，以及先验匹配或从零建图。虚拟场地、阵营和先验地图应相互对应。真车默认 `/dev/nav`，双雷达可以填写 L2 驱动 launch 路径，或沿用已运行的驱动。
2. 匹配模式选择先验地图和与之配套的地形。地形留空时从先验地图目录查找。建图时在工作区 `maps/` 下为本次建图选择专用输出目录。启动建图后默认每 30 秒保存；定时或手动保存成功后都会替换目录的全部内容。
3. 点击「启动系统」。仿真会先启动 Gazebo；匹配和建图模式都会等位姿可信后再启动 Nav2。也可以按进程分别启动、停止和重启。停止 Gazebo 会依次关闭网页启动的 Nav2 和定位，停止定位也会关闭网页启动的 Nav2。网页会标记同一 ROS 域里由别处启动的节点，这些节点由原终端管理；使用外部建图或定位时，请在网页选择与外部节点相同的模式。
4. 「定位状态」按秒更新，显示等待点云、候选验证及匹配结果。「预览匹配参考点」只显示地图。要直接使用人工位姿，先将车停稳在同一地图的参考点，使 `gimbal_nav` 的 +X 对准所标 yaw。只启动「定位 / 建图」（先验匹配），不要点「启动系统」。在初始化阶段点击「将参考点设为当前位置」，核对坐标和朝向后确认。后端保留当前高度和倾斜，直接把 x/y/yaw 写为定位锚，不做初始点云匹配；后续跟踪与故障检测保持启用。已定位、Nav2 正在运行、地图不匹配、yaw 未标注或前端数据过期时不能使用。确认定位后再自行决定是否启动导航。等待一键启动时可点「关闭全部」打断等待。
5. 建图完成后，停稳，再点「保存地图」并等成功提示。全局重定位前先停止 Nav2 并确认停稳，再点「触发」。服务器从完整先验地图检索描述子，以新点云做几何验证，并按配置连续确认，整个过程无需 UWB。接受请求表示已排队。视野存在相似解时保持位姿未可信，可以到特征更明显的位置停稳后再试。恢复后查看定位状态和位姿，再启动 Nav2。

在「模式与地图 → 常用地形」可收藏、选用或移除「先验地图＋配套地形」组合。仿真和真车分别保存。选用后点「保存启动配置」，下次启动生效，不热切换正在运行的地图。

真车 A4 中 `(0, 0)` 显示「回家」，任一数值非零显示「前往目标点」。普通真车定位导航默认启用「串口意图导航」：导航就绪后，意图桥从启动时加载的 `terrain.json` 取同名 `home` / `target` 标点，向 Nav2 发送 `map` 目标。重复意图不重复发送，缺标点不回退到原始数值或原点。关闭开关会请求取消意图桥自己的目标，不是整车急停；重新开启后，新收到的意图可以再次触发导航。更改标点后，导出到启动所用地形目录并重启导航。断流后工作台显示「上次接收」。A3 下发速度仍单独显示，写出不等于板端确认。

从零建图时，Nav2 不读取离线地形文件，而是根据实时雷达生成 8 × 8 米的局部和 30 × 30 米的全局滚动代价地图。窗口大小不代表雷达已观测范围。可在 Foxglove 查看 `/global_costmap/costmap`，用单点导航发送 `map` 坐标。目标尚未观测、超出滚动窗口，或未知区域挡在途中又没有可行绕路时，车只沿目标方向驶到已观测且留有车身余量的位置，再用新的雷达观测重规划；没有安全进展就停止，不把临时停车点算作到达。多点导航仍要求各路点可直接规划。模式限速 0.5 m/s，保留定位可信、雷达观测超时和碰撞监控保护，不启用地形分区、旋转或倒车恢复。请仅在平坦开阔场地使用，不用于坡道、台阶、落差或窄通道；复杂地形请先制作导航地形，再切换到先验匹配模式。

「参数调整」为仿真与真车分别保存参数。导航可调整速度和加减速度上限、速度前瞻、到达容差、无进展超时、规划代价权重和两级代价地图的膨胀参数。定位与建图可调整跟踪校正周期、子图半径和帧数、点云累计时间、开机搜索半径、重定位候选数和确认次数、建图关键帧间隔及回环子图半径。空值使用对应平台及雷达配置的默认值。保存后重启相应的 Nav2 或定位进程，使参数生效。参数覆盖和日志位于 `log/web_ui/domain_<ID>/`。

真车的「参数调整 → 定位与建图」包含「雷达近距软件过滤」，默认 0.30 米。它同时设置点云合并和定位前端的距离下限，在下次启动「定位 / 建图」时生效，不改变雷达的硬件探测范围。

真车的「普通地形速度上限」调整最终速度上限，不会提高 `nav2_real.yaml` 中独立的路径跟踪参考速度。

## 离线优化与地形标注

1. 保存地图并停止对应建图任务。在「离线地图优化」选择已保存的输入地图和 `maps/` 下的输出目录。「开始优化」后可查看日志或取消。优化成功会替换已有输出目录的全部内容。单雷达可启用射线过滤并填写保存点云坐标系中的光心。多光心的双雷达地图可沿用关闭射线过滤的默认选项。首次使用需安装并编译[离线优化器](../src/mapping/offline_mapping_optimizer/README.md)。
2. 将 STEP 场地文件放入工作区 `maps/field_models/`，在「地形标注 → 场地模型」选中文件并点「打开场地」。文件名在工作区内唯一时，也可仅输入文件名。`.step` 和 `.stp` 均受支持。STEP 原点留空时，`RMUL2027_3V3_V1.0.0` 使用与 Gazebo 一致的坐标，其他模型沿用 RMUC2027 的默认原点。首次加载大型文件可能需要几分钟。已保存的场地 `.surf.npz` 工程也可直接打开。
3. 在俯视图选中面片，设置类型、通行性和方向。可用画笔、矩形、套索和切割线修正范围。手动方向从当前坐标系正 X 轴开始逆时针计角。保存场地 `.surf.npz` 工程即可复用标注。
4. 切换到「建图点云」，打开已建图的目录、PCD 或点云 `.surf.npz` 工程。从离线优化页点「标注输出地图」也可带入输出路径。两个工程可来回切换，切换时保留各自的修改。在同一工作区打开新来源会直接丢弃该工程的未保存修改，请先保存需要保留的内容。
5. 在「点云配准到场地」选择「配准参考」并点「载入参考」。可选场地模型、场地标注工程或已有建图 `.surf.npz` 标注工程。建图工程作为参考时不会替换当前点云，初值应填写当前地图到参考地图的 X/Y/Z 平移和航向，而不是参考工程曾使用的场地配准。也可使用匹配的工程初值或从已有地形的 `terrain.json` 读取初值。运行 ICP 后，查看青色参考边界、残差及内点率，确认对齐再点「采用参考面片与标注」。
6. 「采用参考面片与标注」把参考地形投影到当前 `map` 坐标系。凡参考工程有有效高程和标注，静态地图就采用参考的面片、类型、方向、通行属性、地面高程和净高，包括点云空洞、扫描边界以外和扫到新障碍的区域。例如参考为平地而本次扫到箱子，静态地图仍导出平地，不把箱顶当作地面；运行时的实时雷达障碍检测不变。没有有效参考标注时不会自动标为可通行；双方均无高程时保持未知。场地模型仍可用未标注的已知几何补高程。页面的「补齐」计数仅指本次点云缺测格；保存工程后再次做 ICP 仍使用原始观测高程，而不是参考地面。
7. 保存建图标注工程可覆盖同名文件。在 `maps/` 下选择输出目录导出 Nav2 地形，成功后会替换已有目录的全部内容。未标注的有效表面和禁行格导出为障碍。参考工程不会被修改；要更新以前的导出，请在确认配准后重新采用、保存并导出。

在「建图点云」的「工具」里选择家、目标或匹配参考点，再点击已观测的格子。每类只保留一个点；再点一次可移动，亦可清除、撤销或重做。保存工程可保留标点，导出地形后匹配页才能读取。标点均在该建图工程的 `map` 坐标系，不从场地模型或其他参考地图借用。

选择「放置匹配参考点」后，可在已有参考点上输入 yaw 并点击「应用朝向」。单位为度，0° 指向地图 +X，+90° 指向 +Y，逆时针为正。清空输入再应用只清除朝向。保存工程后，导出至运行配置所选的地形目录，匹配预览即可显示方向箭头。旧标点没有 yaw 时显示「未标注」；标注或预览都不会修改实时位姿。

同一个 WebUI 实例共享正在打开的场地和建图工程。多台浏览器编辑时，可通过「读取当前工程」同步。重启服务后可通过路径重新打开已保存的工程。

只想查看标注时，点「地形标注 → 预览已保存工程」，选择或输入服务器上的 `.surf.npz` 工程路径，再点「打开预览」。预览支持场地和建图工程，显示地形俯视图、类型图例、标注数量及禁行斜纹，可放大查看，不会替换当前工程或丢弃未保存修改。若找到源自匹配模式先验地图的工程，预览会优先选中并标明两者一致。建图工程以其真实的 `map (0, 0)` 为锚点绘制坐标轴（`+X` 向右、`+Y` 向上）；原点在图外时会提示，不会把它移到图边或以栅格左下角代替。点击图中任意一点会标记该点，并在图上方显示该工程 `map` 坐标系下的 X/Y（米）。场地工程不显示地图原点，也不提供 `map` 坐标。

### STEP 解析环境

新机器按下面的命令创建基于 Ubuntu 系统 Python 的环境，使 WebUI 能同时使用 ROS 2 Jazzy 的 Python 模块和 STEP 解析器。安装后重启 WebUI 服务。

```bash
sudo apt install python3-venv
python3 -m venv --system-site-packages ~/.venvs/nav-terrain
~/.venvs/nav-terrain/bin/python -m pip install cadquery-ocp
```

`tools/start_web_ui.sh` 优先使用 `YANG_NAV_WEB_PYTHON` 指定的解释器，其次使用已激活的 Python 虚拟环境，再尝试 `~/.venvs/nav-terrain/bin/python`。已有包含 `cadquery-ocp` 的环境时，也可以把该环境的解释器绝对路径配置到 systemd 服务的 `YANG_NAV_WEB_PYTHON`。

## 录包与 Foxglove

- 真车摘要录包由 `nav_bringup/navigation.launch.py` 启停。通过 WebUI、`tools/start_navigation.sh` 或 `ros2 launch` 启动真车导航均默认开始录包；停止该 launch 时封包。只开 WebUI 或只启定位不录。真车单次关闭可传 `auto_bag:=false`，WebUI 勾选框向 launch 传递相同开关。已有录包时不替换它。仿真的 WebUI 自动录包行为不变。
- 轻量摘要也记录串口地点意图和单点规划 Action 状态；使用 4 MiB 缓存，有消息时每 30 秒滚动关闭一个 MCAP 分片。断开浏览器或 SSH 不会停止服务端录包；正常停止会生成整包元数据。强杀时最后一个分片可能不完整，已关闭的分片可用 `ros2 bag info -s mcap <分片路径>` 单独检查。分片不能保证突然掉电时零丢失。
- 每 5 秒检查 5 GiB 剩余空间及约 256 MiB 单会话限额；达到限制只停止录包，不停止导航，也不删除旧包。完整传感器回放仍需手动录包。

- 「开始录包」使用项目的 `record_bag.py`。可设时长、备注、追加话题或录制全部话题。仿真自动使用 `/clock`。录包目录位于 `bags/recordings/`。话题边录边写；停录后先写完缓存并封包，再并行检查包信息和采集 ROS 诊断。每次诊断快照共享一个参数查询时限，跳过的节点记录在相应的 `snapshot.yaml`。待「录包已保存」后再关闭 ROS 节点；点击「关闭全部」也会先等待录包收尾。
- Foxglove Bridge 由 systemd 开机启动和故障重启。Ubuntu 主机已有对应服务时直接使用。首次部署可执行 `sudo apt install ros-jazzy-foxglove-bridge`，再以运行 ROS 的用户执行 `bash tools/install_foxglove_service.sh`。默认地址为 `ws://主机局域网IP:8766`，用于查看点云、TF、路径和代价地图。自定义端口时，安装脚本的端口参数和 WebUI 的 `--foxglove-port` 应一致。可用 `journalctl --user -u yang-nav-foxglove.service` 查看服务日志。
- 终端按 Ctrl+C 会退出 WebUI，并按顺序关闭由本次 WebUI 启动的进程。
